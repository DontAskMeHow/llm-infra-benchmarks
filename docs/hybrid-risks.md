# Риски гибридных моделей на паре (QSA + GDN + PLE + attention)

Пилот Qwen3.8-Flash-Next — гибрид (48 текстовых слоёв, QSA/внимание/mamba-блоки;
attention+mamba, page size 3200 выровнен по mamba). Каталог багов prefix-cache гибридов
из пакета handover держим локально (не публикуется); здесь — то,
что относится к нашему стенду, + наше состояние 18.09.

## Что у нас на стенде (18.09)

- **fp8-KV теперь работает**: в пакете для пилота «KV только BF16» (QSA-ядра реджектили
  fp8); в ночнике 17.09 fp8-KV работает — отсюда 2.70M токенов KV на 20.39 GiB. Это наша
  находка, отражённая в бенчах: KV 691K → 2.70M.
- **MTP-ограничение** (лог worker; имена подсистем обобщены): «Draft model <MTP> does not support external
  multimodal embeddings» и «fused multi-step draft decode is not supported by attention
  backend <QSA-state> — fallback to rebuilding attention metadata between draft
  steps». Т. е. для vision-входов MTP идёт по обрезанному пути, fused multi-step не
  доступен — часть потенциала MTP3 не реализована.
- **Ведж >100K — ЗАКРЫТ 19.09.** В пакете зафиксирован ведж пары при ~3-м подряд
  длинном (>100K) запросе (кейс 4×Spark, YaRN-1M). Наша серия 5×200K подряд (19.09,
  новые промпты, c=1) — 5/5 успешно, веджа нет: TTFT ~63.6 c стабильно, KV пик 8.8%,
  RAM 13–15 GiB available, NVRM чистый, earlyoom не срабатывал. Артефакт:
  `artifacts/gb10/wedge-test-2026-09-19.md`. Остаточный риск — серии близко к 512K.

## Диагностическая шпаргалка (если вывод — мусор/каша)

Проверять по порядку (из каталога пакета):

1. MTP включён? У рекуррентных архитектур rejected-draft-состояние не откатывается —
   классический источник мусора. У нас MTP3 в бою, но на свежей паре вывод чистый.
2. Запрос с общим префиксом? Сравнить со свежим уникальным промптом: мусор только на
   кэшированных → порча в кэше (GPU prefix cache; лечится рестартом пары).
3. Конкурентные префиллы? (chunk-выравнивание recurrent state; в свежих vLLM частично
   починено).
4. После рестарта пары — повторить; если чисто, порча была в кэше (gpória: «poison» живёт
   в GPU-памяти, чистка L1-кэша не помогает).

## Красные линии конфига (с точки зрения рисков гибридов)

- **LMCache/CPU-KV-offload на пару не ставить**: unified-память GB10 не даёт выигрыша,
  а transfer-кернелы LMCache на свежих vLLM у гибридов портят KV молча.
- **max-model-len 524288 — удлинение YaRN×2**: на длинах >100K держать в уме ведж-лакуну.
- **`--max-num-seqs 8`** — малый параллелизм = крупный KV на сессию, но и меньший риск
  конкурентной порчи состояний.

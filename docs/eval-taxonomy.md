# Терминология и ловушки качественных замеров

## Метрики

- **accuracy** — доля точных ответов. **acc_norm** — MCQ: сравнение нормированной строки
  ответа с эталоном (по первой вхожей букве варианта / по последней строке).
- **pass@k** — хотя бы один верный из k семплов; unbiased-оценка по n≥k генерациям.
- **exact match** — полное совпадение после нормализации (для математики обычно проверка
  `\boxed{}`).
- **PPL/CE** — exp(средний cross-entropy): «удивление» модели на тексте. Сравнивать
  только внутри одной экосистемы (токенизатор/движок): у vLLM известен численный дрейф
  logprobs против HF (vllm#21475).
- **эффективная длина (RULER)** — порог accuracy ниже результата Llama-2-7B на 4K.

## Ловушки

- few-shot задаётся бенчмарком (GPQA — 0-shot, MMLU-Pro — 5-shot); смешивать нельзя.
- Фиксированный seed/общие префиксы загрязняют prefix-cache (cold становится warm).
- thinking-модели: ответ смотреть только в `content` (после reasoning); мышление ест лимит
  генерации — обрезка по max_tokens может срезать финальный ответ (помечать finish_reason=length).
- temp=0 на thinking-модели может занижать рассуждение; эталон NVIDIA гнал на temp=1.0 —
  наши батареи на temp=1.0, reproducibility ниже, сопоставимость выше.
- LLM-judge смещён (позиция, многословие) — предпочитаем бенчи с объективным ground truth.
- Контаминация: свежие вопросы (LiveBench/LiveCodeBench) контролируют её; для GPQA/MMLU
  риск есть, но для «не сломался ли наш конфиг» не критичен (смещение константой).
- Срезки: погрешность ±3–8 п.п. при `--limit` 10–50 (канон Model-Optimizer researcher guide).
